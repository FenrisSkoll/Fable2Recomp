# G1.5C completion

## Result

**PASS WITH LIMITATIONS**

The exact G1.5A ReXGlue implementation and exact G1.5B Xenia Canary revision
have been compared across all 13 required GPU subsystem areas. The result is a
deterministic 37-record divergence matrix, a 30-record primary-history corpus,
classification and rationale chapters, and an extended read-only verifier.

The limitations are material but non-blocking: this was a static source and
history audit; the Canary clone is shallow; one port origin and one async
origin commit remain unavailable; broad diagnostic equivalence is incomplete;
and 21 behavior records remain **UNKNOWN FOR FABLE II**. No visual symptom was
promoted into a cause, no implementation was selected, and no runtime
instrumentation was needed.

## Most consequential confirmed divergences

Without selecting an implementation, the strongest guest-visible candidates
are:

- nonzero hardware reset-register defaults in Canary versus zero-only ReXGlue;
- segmented, cross-submission ZPD report lifetime versus ReXGlue's active
  single synchronous D3D12 query;
- zeroed out-of-bounds vertex lanes and real XPS backing/address wrapping in
  Canary;
- texture backing-validity, integer scaling, Q16 rounding, separate base/mip,
  promoted-1D, and literal-only binding changes;
- canonical EDRAM sample addressing, guarded scaled-resolve readback, gamma and
  fixed-number resolve conversion, and extended Xenos float16 handling;
- Canary's generalized scalar approximation rounding versus ReXGlue's retained
  title-specific tessellation workaround, with exact hardware precision still
  unconfirmed;
- cross-submission asynchronous pipeline work, constant-alpha host-capability
  fallback, and unwatched mapping lifecycle invalidation;
- different guest-vblank/host-pacing policies; and
- ReXGlue's mandatory plugin ABI, split setup, ownership, and active D3D12-only
  deployment boundary.

These are confirmed source differences, not confirmed Fable defect causes.
