# Xenia Canary textures, vertex fetch, and samplers

## Evidence basis

All source locators refer to
`xenia-canary/xenia-canary@3a44f20c7bc66db1da583e8a6f0ab740e31908e9`.

## Texture identity

`src/xenia/gpu/texture_cache.cc:TextureCache::BindingInfoFromFetchConstant`
decodes a Xenos texture fetch constant into binding information.
`src/xenia/gpu/texture_cache.h:TextureKey`, nested in `TextureCache`, stores
persistent texture identity and uses
`src/xenia/gpu/texture_util.cc:GetGuestTextureLayout` for layout.

The key includes the state necessary to distinguish guest storage:

- dimensionality and extent;
- base and mip physical pages;
- pitch and tiled layout;
- base and mip levels;
- texture format and endian mode;
- resolution scaling;
- signedness/view requirements; and
- swizzle-related binding state where it affects the view.

Invalid fetch types can be rejected or tolerated according to
`gpu_allow_invalid_fetch_constants`. This is a compatibility/validation
branch, not proof that invalid guest state is correct.

## Guest layout and conversion

`src/xenia/gpu/texture_util.cc:GetGuestTextureLayout` calculates the base and
mip layout. Tiled address helpers, including `TiledOffset2DOuter`, implement
guest tiled addressing. Format information comes through the Xenos format
tables and `FormatInfo`.

The request path is:

```text
analyzed texture fetch binding
  -> BindingInfoFromFetchConstant
  -> TextureKey + guest layout
  -> find/create Texture
  -> SharedMemory::RequestRange
  -> backend LoadTextureData
  -> untile/endian/format conversion
  -> MakeUpToDateAndWatch
  -> descriptor/image binding
```

D3D12 performs this through
`D3D12TextureCache::RequestTextures` and `LoadTextureData`; Vulkan uses
`VulkanTextureCache::RequestTextures` and `LoadTextureData`. The
implementations choose compute/copy operations and appropriate host resource
states/layouts. The transformation chain is **CONFIRMED**; the chosen path for a
specific texture/device is **UNKNOWN**.

## Cache, residency, aliases, and invalidation

The shared `TextureCache` owns:

- the key-to-texture map and most-recently-used tracking;
- base and mip guest-memory watches;
- current texture and sampler bindings;
- signed/unsigned host variants where required;
- memory usage and soft/hard budget enforcement; and
- relationships used by scaled resolves and render-target aliases.

A guest write hitting a watch marks affected base or mip data out of date and
resets bindings. Subsequent requests reload the necessary data. Primary history
commit `9781a75a22ba789124d7f34c6bdb4a85c78b2532`,
`[GPU] Avoid stale texture state after invalidation`, confirms the
non-obvious recheck of validity before installing a watch. This protects
against invalidation racing the transition to watched/up-to-date state.

Soft and hard cache budgets trigger eviction using residency/MRU state.
**UNKNOWN:** static source cannot measure alias frequency, budget pressure, or
whether host residency calls fail on a concrete device.

## Sampler interpretation

`src/xenia/gpu/sampler_info.cc:SamplerInfo::Prepare` combines the fetch
constant with per-instruction overrides. It resolves clamp/address modes,
min/mag/mip filters, LOD range and bias, border behavior, and anisotropy inputs.

Backend caches hash the normalized `SamplerInfo` and create a D3D12 sampler
or Vulkan sampler. Host capability branches may normalize unsupported modes.
The anisotropic-filtering override and non-seamless/cube behavior can
materially change sampling.

- Guest-field decoding is **CONFIRMED**.
- Host normalization and cache ownership are **CONFIRMED**.
- Exact filtering equivalence for all host devices is **UNKNOWN**.

## Vertex fetching

`Shader::AnalyzeUcode` discovers vertex-fetch instructions and produces the
vertex-binding bitmap and per-binding metadata. Before a draw, the backend
requests the referenced shared-memory ranges. DXBC or SPIR-V generated by the
translator performs the fetch, including guest address calculation, data
format decoding, swizzle, signed/normalized conversion, and endian handling.

Thus the boundary is:

```text
Xenos vertex fetch instruction + fetch constant
  -> Shader analysis
  -> shared-memory range request
  -> generated DXBC/SPIR-V vertex-fetch code
  -> host shader input value
```

This is **CONFIRMED** and distinct from the index-buffer path.

## Index buffers and primitive conversion

`PrimitiveProcessor::Process` consumes index address/count/format/endian and
primitive-reset state. If the host topology cannot directly express the Xenos
primitive, it creates/uses converted indices. Guest writes invalidate the
converted range through memory watches.

Implemented cases include 16/32-bit formats, endian transforms, restart/reset,
24-bit index semantics, fan/loop/quad-family conversion, and supported
tessellation normalization. Point/rectangle expansion can occur in generated
shader code.

Backend commands then bind either the original shared-memory index view or the
converted index buffer. The exact host primitive chosen is carried in
`PrimitiveProcessor::ProcessingResult`.
