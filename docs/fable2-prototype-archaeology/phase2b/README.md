# Phase 2B: bounded static semantic evidence

This is a separate, versioned semantic dataset over the **closed** Phase 2A
correspondences. It does not adopt symbols, change discovery inputs, or run a
game. See [report](report.md), [review guide](review-guide.md),
[policy](policy.md), and [next-phase handoff](phase2c-handoff.md).
Exact completed checks are recorded in [verification.md](verification.md).

## Reproduction

Use PowerShell 7 in `C:\Dev\Fable2Recomp`, branch
`fable2-prototype-archaeology-phase2b`. The source pins require the original
private corpus at `D:\Fable2-Recomp\prototypes`, the existing ignored Phase 1
derived sections and Phase 2A exhaustive artifacts, the retained current
closure/coverage/map inputs, and the pinned Python runtime. Missing or changed
inputs are errors, not instructions to regenerate Phase 2A.

```powershell
python tools/VerifyFable2PrototypePhase2AConsistency.py
python tools/Fable2PrototypeSemantics.py generate
python tools/Fable2PrototypeSemantics.py verify
.\tools\Verify-Fable2PrototypeSemantics.ps1
python -m unittest discover -s tests -q
git diff --check
```

`generate` and `verify` both hash every source, run Phase 2A consistency checks,
perform bounded analysis, reconcile the evidence family and audit forbidden
changes. `verify` compares all generated bytes without writing. The PowerShell
command validates all eleven JSON documents against the committed JSON Schema;
it does not download schemas. The unit-test discovery command is intentional:
some existing suites import helpers from the discovery directory.

The one-time `bind` command was used before generation. It refuses to replace
existing source pins. Do not delete pins or rebind to work around a failure.
The exact close-out commit/tree and 1,409 input identities are in
[semantic-source-pins.json](evidence/semantic-source-pins.json). Implementation
file hashes are separately included in the validation artifact; the current
Git HEAD and wall clock do not change analytical payloads.
Scoped `.gitattributes` additions preserve LF bytes for Phase 2B implementation
and evidence on Windows checkouts; the audit rejects any other attribute delta.

## Evidence locations

The committed [validation](evidence/semantic-validation.json) binds nine
exhaustive JSON artifacts under `out/prototype-archaeology/phase2b/` by relative
path, byte size and SHA-256. Their families are inventory, XREFs, registrations,
terminal index, accepted subset, stratified review, mapping review, bounded
graph and scalar/global candidates. The generated report is also hash-bound.
The single schema is
`tools/schemas/fable2-prototype-semantics-v1.schema.json`; each document has its
own explicit schema name and version 1. Shape validation is supplemented by
`validate_family`'s reference, mapping, ownership and acceptance invariants.

The community file is retained only in the ignored `external/community-lua.txt`.
It was downloaded once from the exact raw URL in the source pins, commit
`8ba7f3d9807e8566475afb5e54f478b235fc309a`, and verified as SHA-256
`A46F45954371927A89DEB51AA9D3372916C2F74CC86BBB944E4F90F1D3324D3F`.
It is not redistributed here. Parsing accepts standalone namespace headers
and identifier lines, stripping `--` comments; it does not expand slash lists
or infer signatures. Every line has a decision and line hash in the ignored
inventory, while normalized names preserve line provenance. Unavailable or
hash-mismatched community input is recorded as unavailable at initial binding;
an already bound available input cannot silently disappear.

## Review and safety

No canonical naming file, manifest, override, generated source, runtime,
renderer, SDK dependency or binary input may change. Output paths resolve only
inside the two approved Phase 2B roots. The Git audit checks every tracked and
untracked change against a narrow allowlist, including committed changes since
the exact Phase 2A close-out. ReXGlue's branch, HEAD, tree, remotes, status and
all fifteen pre-existing materialized libmspack file identities are checked.

The complete repository test discovery covers Phase 1/2A, maps, closure,
ownership, indirect targets and coverage as well as the new synthetic fixtures.
No existing test expectation was weakened. The report is generated, not edited
by hand; deterministic verification detects report/summary/ignored-byte drift.
